Building a Dashboard with Quarto: vehicletrends.us

It’s a Quarto website

project:
  type: website

website:
  sidebar:
    contents:
      - about.qmd
      - vmt-daily.qmd
      - depreciation.qmd
      - percent-listings.qmd
      - market-concentration.qmd
      - registrations.qmd

15 pages. ~2,900 lines of markdown.

The agent writes the .qmd.

The data lives in an R package the pages load at render:

library(vehicletrends)

It never touches the numbers.

Every page gets a URL

  • vehicletrends.us/depreciation — link it, bookmark it, send it to someone
  • the back button works
  • search engines index it
  • 10 pages in the sidebar, 10 addresses

A Shiny app is one URL. The state lives in a session.

No UI. No server.

Shiny

  • a UI
  • a server function
  • a reactive graph
  • a process that has to be running

You maintain an application.

Quarto

  • markdown
  • a chunk that returns a widget

You maintain a document.

Real compute over data too big for a browser is Shiny’s job. This isn’t that.

No input. No server. No reactive.

View map in new tab

Need something heavier? Put it in a box

The census-tract map is the hardest thing on the site: 276 lines of hand-written MapLibre and 1.64 GB of map tiles on a CDN.

It’s not in the dashboard. It’s its own repo — hhi-map — built and iterated in isolation, then dropped in:

htmltools::tags$iframe(
  src = "https://vehicletrends.github.io/hhi-map/",
  height = "700px", width = "100%"
)

Or drop a whole Shiny app in the page

Two pages on the site are Shiny apps — compiled to WebAssembly, running in the reader’s browser:

```{shinylive-r}
#| standalone: true
#| viewerHeight: 800
```

Same move. The hard thing goes in a box, and the page just says where.

Small pieces have small context windows

Isolate a component →

  • the agent holds all of it in one context
  • you iterate on it without touching the site
  • it drops back in as an iframe

The agent opens one page — 200 to 600 lines. Never the site.

The whole dashboard is never in scope at once. Neither is the token bill.

It’s just static files

Everything here runs in the browser, and the whole site is files — hosted for free.

  • charts → ECharts (JS), rendered client-side
  • the map → PMTiles on a CDN, instant
  • the Shiny app → Shinylive, compiled to WebAssembly. No server.

A GitHub Action re-renders and republishes it every Sunday at 5am. Nothing is cached, so nothing goes stale.

No server to run. No server to secure. No server to pay for.
